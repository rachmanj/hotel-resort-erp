## Findings (priority order)

### HIGH — Hard Gate

**1. R-34 (theme must work in both modes) — hardcoded light colors break dark mode in 3 components**
- `resources/js/Pages/Profile/TelegramLink.tsx:79` — success card hardcoded `background: '#f6ffed', borderColor: '#b7eb8f'`. In dark mode the card stays light green while text becomes light → contrast failure (also R-25).
- `resources/js/Pages/Reservations/components/AvailabilityGrid.tsx:33` — selected row `background: '#e6f4ff'` (light blue). In dark mode the light blue row with light text fails contrast.
- `resources/js/Pages/FB/KitchenDisplay.tsx:112` — `borderBottom: '1px solid #f0f0f0'` (near-white separator). Renders as a bright line on the dark background.
- Fix: derive from antd token (`token.colorBgContainer`, `token.colorSuccessBg`, `token.colorBorderSecondary`) with `useTheme()` isDark switch, matching the pattern already used in `Reservations/Calendar.tsx`.

### MEDIUM — Purpose-Gate

**2. R-08 (arrows are not the default identity for every button) — decorative arrow**
- `resources/js/Pages/Housekeeping/Index.tsx:76` — `Manage Assignments →` (arrow is pure decoration on a Tag link).
- Fix: remove the `→`, keep `Manage Assignments`.
- Note: the `X → Y` date-range arrows elsewhere (Agents/Rates, Promotions, Groups/Show) and `Preparing → Ready` (KitchenDisplay) are functional range/flow indicators, not decoration — those are fine.

### LOW — Quality Locks

**3. R-03 (44px minimum tap target) — partial**
- `controlHeight` is set to 40px (antd Large). Close to, but below, the 44px minimum in R-03. Functional on mobile but not strictly compliant.
- Fix (optional): raise `controlHeight` to 44 in `app.jsx`, or accept 40px as the antd-native touch-friendly size.

**4. R-20 (visual identity consistency) — login brand name mismatch**
- `resources/js/Pages/Auth/Login.tsx:22` shows "Pratasaba Resort" while the app title is "Pratasaba ERP". Likely intentional (resort = hotel brand, ERP = software), but the two names should be reconciled so users see one consistent brand.
- Fix: decide one name, or keep "Resort" on the login card and "ERP" in the authenticated shell with a documented reason.

**5. R-27 (empty/loading/error states must be informative) — generic empty states**
- All ProTable lists rely on the antd default empty state ("No data" / empty icon). It names neither the cause nor the next action.
- Fix: add per-page `locale={{ emptyText: <custom/> }}` or `emptyText` that says why the list is empty and the one action to fill it (e.g. "No reservations yet. Create the first one.").
