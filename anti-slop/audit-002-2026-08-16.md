## Findings (priority order)

### HIGH — Hard Gate

**1. R-02 — Em dash `—` in backend user-facing strings (~27 occurrences, ~20 files)**

The prior pass only scanned `resources/js/`. Backend PHP and Blade strings still contain em dashes, all user-facing:

- Telegram bot output (13 command files): `HelpCommand`, `RoomsCommand`, `PromoCommand`, `KdsCommand`, `GlCommand`, `CheckInCommand`, `AgentBookingsCommand`, `GroupsCommand`, `MyRoomsCommand`, `ReportCommand`, `AvailableCommand`, `WorkOrdersCommand` — e.g. `/start — Welcome & link instructions`, `%s — %s (%s)`, `• %s — %s`.
- Activity log descriptions: `app/Http/Controllers/Admin/ActivityLogController.php:82,105` — `"Reservation X cancelled — reason: ..."` (shown on the Activity Logs page).
- Folio item / action descriptions: `app/Actions/Reservations/CheckInGuestAction.php:79,106`, `app/Actions/Groups/DeductGroupDepositAction.php:55` — `"Room X — N night(s)"`, `"Group deposit credit — CODE"` (visible in folio line items).
- `app/Services/AgentCommissionService.php`, `app/Notifications/VipGuestAlertNotification.php` — user-facing text.
- `app/Http/Controllers/Reports/ConsolidatedReportController.php:14` — "coming soon" message.
- `resources/views/invoices/folio.blade.php` — the printed invoice template.

Fix: replace `—` with `,`, `:`, `·`, or restructure. (Exempt: `CheckOutGuestAction.php:118` "Zero commission — skip accrual" is a code comment, not UI text.)

**2. R-34 / R-25 — Hardcoded grey text `#666` breaks dark-mode contrast (6 locations)**

`#666` on the antd dark background (`#141414`) computes to ~3.1:1, failing WCAG AA (4.5:1) for normal text. These are unconditional colors (not `isDark ? token : '#hex'`), so dark mode is broken:

- `resources/js/Pages/Housekeeping/Index.tsx:115` — `color: '#999'` (11px; passes AA but small text should be higher)
- `resources/js/Pages/AgentPortal/Bookings/Index.tsx:54` — `color: '#666'`
- `resources/js/Pages/Folios/Invoice.tsx:50` — `color: '#666'`
- `resources/js/Pages/Groups/Create.tsx:186` — `color: '#666'`
- `resources/js/Pages/Reservations/components/CheckInModal.tsx:53` — `color: '#666'`
- `resources/js/Pages/Reservations/components/CheckOutModal.tsx:99` — `color: '#666'`

Fix: use `theme.useToken()` → `token.colorTextSecondary` (matches the pattern already used in `Calendar.tsx`).

### LOW — Quality Locks

**3. R-27 — Empty states are present but generic (not actionable)**
- Global `renderEmpty` shows "No records yet" for every table. It names neither the cause nor the next action (antislop-ui: "an empty state says why it is empty and gives the one action that fills it").
- Fix (optional, larger): per-page `emptyText` for the key lists (Reservations, Guests, Rooms, Groups, F&B Orders) — e.g. "No reservations yet. Create the first one." with a CTA.

### Not flagged (checked, deemed compliant)
- `→` in date ranges (`valid_from → valid_to`, `Preparing → Ready`) — functional range/flow indicator, not decoration (R-08).
- En dash `–` as empty-value placeholder and date-range separator — typographically correct for ranges; R-02 bans the em dash specifically.
- Consolidated report "coming soon" — honest, visible placeholder (R-26 compliant); its only issue is the em dash in its message (covered by finding 1).
